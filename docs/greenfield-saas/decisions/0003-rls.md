# ADR 0003 — RLS forced on every tenant table

Status: accepted (2026-11-20)

## Context

Multi-tenancy fails at the one hand-written `WHERE` someone forgot. The product's
output is credentials, so a leak is the worst kind: silent, and wrong until a
tenant notices.

Repo-level scoping alone is discipline. A database-level backstop is cheap here
because every plane connects with a role we control.

## Decision

Every table with `org_id`: `ENABLE` + `FORCE ROW LEVEL SECURITY`, policy on
`current_setting('app.org_id')::uuid` for both `USING` and `WITH CHECK`. The runtime
role is not the owner. A service-scoped `edge_ro` role reads by `app.service_id`
through equivalent policies. CI walks `information_schema` and fails on any
unprotected table.

Repos still filter by `org_id`, because RLS is a backstop and needs the GUC set by
a wrapper that can itself be forgotten.

## Consequences

- A missing GUC yields zero rows, not all rows — the safe failure.
- Every transaction must set the GUC; a raw query without it returns emptiness.
- `app_admin` has `BYPASSRLS`; admin blindness is then a key problem, not a row
  problem (ADR 0017).
- Migrations must add the policy in the same transaction as the table.

## Rejected

- **Application-only scoping.** One forgotten filter is a leak, and it is invisible
  in review.
- **Schema per tenant.** Migration fan-out and cross-tenant joins for admin get
  ugly at hundreds of tenants.

## Reversal cost

Low to drop, high to add late. That asymmetry is why it is stage 2, before any
route.
